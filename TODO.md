# BLASTER BRAWL — Phase 1 and Phase 2 outcomes

## Phase 1 (completed)

- [x] **Canvas runtime and project structure** — Build an original 2D browser platform gun-fighter called “BLASTER BRAWL.” Do not copy any existing game's name, art, sprites or sounds. Put the title and all tunable values in `src/config.ts`. Use TypeScript + Vite, a custom engine on HTML5 Canvas (no Phaser), a fixed-timestep loop at 60 FPS, and object pooling for bullets and particles. Keep a modular structure for scenes, entities, weapons, UI and config. Use minimal dependencies with pinned versions and Vitest for unit tests.
- [x] **Arena, fighters and ring-out match** — Provide one map with grassy floating platforms and brown rocky bases, plus a simple parallax background containing sky, mountains, huts and acacia trees. Provide two fighters: one human and one simple bot that walks toward the human and shoots. Do not add difficulty levels. Use a health-free knockback system: every hit pushes the opponent back; the goal is to knock them off platforms. Give each fighter 3 stocks, respawn on death, and declare the last fighter standing the winner.
- [x] **Controls and weapons** — Support A/D or arrows for movement, W/Up for jump and double jump, J or Space to shoot, K to switch weapon, and Esc to pause. Include pistol, shotgun and rocket launcher; each has distinct fire rate, damage, knockback, recoil and ammo. Spawn random weapon pickups on the map.
- [x] **Animation, feedback and scene loop** — Include small idle, run, jump, shoot, hit and fall animations. Provide particles for muzzle flash, bullet trails, dust and explosions. Include screen shake with an adjustable intensity setting. Implement the full loop: title menu → match → victory/defeat screen with replay button → back to menu.
- [x] **Menu and presentation** — Use right-aligned bold white menu text with a thick dark outline over the game scene. Include CAMPAIGN, CUSTOM GAME, GUN LIBRARY, OPTIONS and CREDITS; only “Play” needs to work in Phase 1 and the others may show “Coming soon.” Give the title chunky metal-rivet lettering and support keyboard navigation in menus.
- [x] **Original art and audio** — Use a bright cartoon flat-vector style with thick black outlines, round-headed simple-bodied characters, customizable hat and color. Create all art procedurally in Canvas/SVG; use no external assets. Keep the game child-friendly with cartoon violence only: no blood and no real weapon brands. Generate sound procedurally with Web Audio API; use no external files or licensed audio. Audio must start only after the first user click. Include a persistent mute button.
- [x] **Robustness, settings and security** — Include a loading screen with progress bar, friendly error screen and global error handler. Scale the canvas responsively and support fullscreen. Treat localStorage settings as untrusted: validate them against a schema, version the data, and reset safely if corrupt. Use no inline scripts and no `eval`/`new Function`. Provide a `_headers` file with a strict CSP, X-Content-Type-Options, frame-ancestors, Referrer-Policy, Permissions-Policy and HSTS.

## Phase 2

- [x] **Difficulty-aware bot AI** — Add three difficulty levels (Easy / Normal / Hard), all tunable in `src/config.ts`: reaction time delay; aim accuracy and aim error; fire discipline (burst vs. spray); dodge chance against bullets and rockets; and weapon pickup priority. Bots must move toward or away from targets, aim, jump and double jump, shoot, dodge incoming projectiles, grab weapon pickups, and recover back onto platforms after being knocked off (use double jump, steer toward the nearest platform edge). Bots must never get permanently stuck; add a stuck detector that triggers fallback behavior. Easy should feel beatable by a beginner. Hard should be tough but fair (no wallhacks, no perfect aim). Keep AI as pure helper functions where possible so they can be unit tested.
- [x] **Modes and reusable match setup** — Support 1v1 vs bot; 1v3 free-for-all (you + 3 bots, each fighter for themselves); local 2-player on one keyboard with P1: A/D move, W jump, J shoot, K switch weapon and P2: Arrow keys move, Up jump, Enter or Numpad0 shoot, Right Shift switch weapon; Escape pauses for both. Support 2 players + bots (e.g. 2 humans vs. 2 bots free-for-all) through the same reusable `MatchConfig` (mode, bot count, difficulty, stocks, weapons on/off).
- [x] **Custom Game screen** — Wire MatchConfig to a simple keyboard-navigable Custom Game screen in the same right-aligned bold outlined menu style. Let players pick mode, number of bots (1–3), difficulty, stocks (1–5), weapons on/off, then Start. The Preview confirmed keyboard entry and the Free-for-All three-bot default; the full custom-match result loop is still outstanding below.
- [x] **Multi-fighter HUD and FFA results** — Show name labels above every fighter (“Player 1”, “Player 2”, “Bot 1”, “Bot 2”...). Use colorblind-friendly fighter colors, with each also marked by a distinct shape or number icon beside the label. Show a per-fighter stock counter and current weapon/ammo display. Show offscreen indicator arrows for fighters knocked far off the map. Show elimination order and a clear winner announcement in free-for-all. Source/build and match-result tests pass; the live four-fighter HUD and edge arrows were observed in Preview. The FFA result/replay transition remains part of the uncompleted full mode walkthrough.
- [ ] **Balance, recovery and performance** — Respawn with brief invulnerability and a visible flicker. Choose spawn points away from enemies. Scale weapon pickup spawn rate sensibly with the number of fighters. Maintain 60 FPS with 4 fighters plus projectiles and particles; if it drops, add an automatic particle quality-lowering option. The simulation is fixed at 60 Hz and particle quality scales down after repeated slow-frame observations, restoring after sustained fast frames. The quality response is implemented, but actual frame rate was not measured on a physical device.
- [ ] **Phase 2 tests and verification** — With Vitest, cover bot decision helpers for target selection, dodge decision, recovery direction and stuck detection; verify difficulty parameters stay within valid ranges; verify free-for-all win condition and elimination order; and verify respawn invulnerability timing. Walk through each mode (1v1, FFA, local 2P, 2P + bots) from menu to match to results to menu, fix bugs found, and run a headless bot-vs-bot simulation for each difficulty to check that matches finish and bots never freeze. Be honest about anything not verified. Automated checks, a live FFA HUD/pause Preview pass, and the partial Custom Game walkthrough are complete; full results/replay flows across all modes remain unchecked in `QA_CHECKLIST.md`.
- [x] **Phase 2 handoff** — Deliver updated source, an updated README with a controls table and config options, a short test report, and a list of files changed.


## Phase 3 — mobile support

- [x] **Touch controls** — The left side has a virtual joystick with dead zone for left/right movement and a separate Jump button. The right side has Jump, Shoot, Switch Weapon and Pause buttons. Move and shoot work simultaneously; pointer events are tracked by pointer ID. Touch handling uses Pointer Events, `touch-action: none` and default prevention to prevent scrolling, pinch/double-tap zoom and text selection. Semi-transparent thick-outlined controls follow the game art; action targets are at least 48px and use safe-area insets. Controls appear on touch devices or when manually enabled in Options, and keyboard/gamepad input hides them. Options save control size, opacity, left-handed layout and haptic feedback (`navigator.vibrate` where supported). Local 2-player remains keyboard-only; touch Custom Game identifies and blocks it with an explanation.
- [x] **Landscape layout and menus** — The game is landscape-first. Portrait displays a “Rotate your device” overlay and pauses the match; rotation back resumes without a catch-up step. Canvas sizing supports `100dvh`, viewport/address-bar resize and orientation changes, with device-pixel ratio capped at 2. Canvas menu, options, custom-game, pause and result interactions remain pointer/tap selectable; touch controls have large hit targets. Fullscreen is offered where supported, and iOS Safari receives an Add to Home Screen hint when the Fullscreen API is unavailable.
- [x] **Performance and lifecycle** — AUTO measures the opening 120 animation frames (about two seconds) against 50 FPS and lowers particle emission/cap, shake and parallax when below target; Options also offers LOW and HIGH. The existing projectile, pickup and particle object pools remain bounded; touch input reuses its per-frame state and no longer allocates temporary key arrays. The match pauses on `visibilitychange` and blur, and the audio context is safely suspended/resumed. Web Audio unlocks on the first pointer/touch gesture.
- [x] **PWA and offline shell** — Add a manifest with landscape orientation, standalone display, theme color, 192px/512px PNG artwork and maskable icon. A same-origin service worker pre-caches the app shell and built assets, uses cache-first for static built files and removes older versioned caches. The app uses no inline scripts; the existing strict CSP remains in place with same-origin manifest/worker directives. Offline launch is designed to work after the first online load.
- [x] **Phone hosting, docs and automated tests** — Add `dev:host` and `preview:host` scripts. README explains same-Wi-Fi LAN testing, a free HTTPS tunnel and Netlify/Vercel/Cloudflare Pages deployment, and that service workers/fullscreen need HTTPS outside trusted local origins. Unit tests cover joystick dead zone/direction/clamping, simultaneous multi-pointer movement/shooting, action press edges, input-source switching and automatic quality lowering; settings migration and the active particle cap are also tested. Updated README, test report and changed-file list are delivered.
- [x] **Manual mobile QA checklist** — Provide explicit iOS Safari, Android Chrome, notched-device, orientation, low-end-phone, offline and Add-to-Home-Screen checks. Automated/source checks and local HTTP smoke tests passed; no real iOS or Android testing is claimed.
- [ ] **Physical-device follow-up** — Run the unchecked device/release items in `QA_CHECKLIST.md` on actual iOS Safari and Android Chrome and on a low-end phone, including HTTPS PWA install/offline relaunch. This was intentionally not claimed as part of the source-only validation.
